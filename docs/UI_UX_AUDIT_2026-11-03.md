# KK Nutrivet UI and UX audit — 3 November 2026

The biggest opportunity is to make shopping and getting care easier to complete. Preserve the green/cream identity, guest browsing, sticky purchase actions, and shared components. Reduce promotional density, fix misleading states, and make essential information easier to read before adding more visual effects.

Scope: source-based inventory of all 41 screen files, routing, shared theme/components, and selected supporting providers and tests. Deeper review focused on Home, discovery, authentication, product detail, cart, checkout, prescriptions, and care. All 205 existing tests passed (`flutter test --reporter compact`, 55 test files). This is not a rendered-device audit or user study: visual balance, actual contrast, screen-reader output, keyboard interactions, network performance, and production API behavior remain to be validated. Findings below distinguish code-confirmed behavior from design hypotheses. No application code was changed.

## UI priorities and design hypotheses

These observations are grounded in widget structure; their effect on conversion and comprehension needs device and user testing.

1. **Shorten Home and make the selected animal matter more.** `home_screen.dart:137` builds category selection, a hero, featured products, videos, six separate animal rails, prescriptions, bundles, health concerns, multiple trust/story/reward sections, brands, help, and a footer. All six animal rails remain in the layout even when an animal is selected. Proposed order: delivery/search → selected animal → Shop / Consult / Upload prescription → relevant essentials → reorder or active care → one editorial section. Move secondary discovery behind “Explore all animals” and “More care guides.” Aim for users to locate their first useful action without scrolling through unrelated species.

2. **Reduce competing persistent actions.** Home includes Dr. Paw; the shell adds a floating cart and raised Consult navigation. See `home_screen.dart:132` and `main_shell.dart:146`. Keep the primary navigation, one cart summary where useful, and a contextual AI entry. Validate small-screen overlap and bottom-content reachability; overlap has not been demonstrated in this audit.

3. **Use stable, understandable navigation labels.** The shell uses Home / Shop / Consult / Shots / Account, but changes Account to the user's first name or “Sign in” (`main_shell.dart:230,323`). Keep “Account” stable and personalize inside it. Test “Videos” against “Shots,” which can be ambiguous in an animal-care app. Test a care-oriented fourth tab against video engagement before changing the primary navigation; this is a product decision, not a confirmed defect.

4. **Remove unnecessary exit friction.** `main_shell.dart:28` intercepts Home back navigation with an exit dialog. Prefer expected platform back behavior, reserving confirmation for actual unsaved work. Preserve branch history and test back from deep links and login.

5. **Improve small text and custom touch targets.** `lib/core/widgets/compact_product_card.dart` uses 8–10.5px badge/metadata text and 12px names. Search uses a 32×32 submit container and a 16px clear icon with four-pixel padding (`search_screen.dart`). Global 48px button theming does not enlarge arbitrary GestureDetectors. Proposed defaults: body 14–16, secondary 12–14, headings 18–24; use flexible layouts and at least 48×48 logical-pixel Android targets. Do not solve larger-text overflow by clamping text scale.

6. **Make product cards easier to compare.** Use a consistent image area, two-line product name, pack/strength, price, and one purchase action. Limit badges to information that changes the decision: prescription requirement, stock, or a meaningful offer. Put coin earning and secondary promotional details on detail pages. Preserve explicit variant selection and minimum-quantity behavior.

7. **Keep product suitability before upselling.** Product detail places the bundle section before treats/description (`product_detail_screen.dart:241`). Proposed reading order: image/name → species and pack/strength → price/stock/Rx → delivery → use and precautions → details → bundles/related items. Keep the existing sticky purchase bar. Use accordions for long details, with critical restrictions visible rather than collapsed.

8. **Put cart readiness before promotions.** Cart places add-ons, combos, and prescription promotion before delivery and summary (`cart_screen.dart:189`). Proposed order: items → stock/Rx issues → delivery estimate → payable summary → checkout. Keep coupons/coins in one optional expandable row; show one relevant add-on rail after the essential decision information. Preserve discount and partial-COD transparency.

9. **Explain disabled checkout actions where users tap.** `CheckoutStickyPlaceOrderBar` receives only `canPlace` (`checkout_payment_and_review.dart:1386`). Show a specific reason above the button and a resolving action: “Add delivery address,” “Retry delivery check,” or “Prescription review pending.” Keep payment amount and, for partial COD, both pay-now and pay-on-delivery amounts visible. Test whether the additional confirmation modal adds value once the review screen is clear.

10. **Make errors persistent and actionable.** `common.dart` exposes a toast helper and raw-message ErrorView; cart and checkout pass exception strings. Use plain-language inline errors for recoverable tasks, keep form input, and offer Retry/Edit/Contact support. Reserve brief snackbars for nonessential confirmations. A failed scan must not settle on the same state as a successful scan with no matches.

11. **Distinguish care channels consistently.** Preserve the existing AI labeling in Dr. Paw and emergency guidance in health content. Use consistent labels across Home, Account, PDP, and chat: “Care team chat,” “Book a vet,” and “Dr. Paw · AI assistant.” Explain response expectations and any payment before users invest in intake. AI-to-human handoff should carry animal and question context with user awareness. This recommendation concerns interface clarity, not a clinical review of advice.

12. **Make motion optional and restrained.** Shared motion includes bounce/slide effects; the hero auto-advances; navigation uses Lottie; videos autoplay when active. No `disableAnimations` or `accessibleNavigation` handling was found in `lib`. Respect reduced motion, pause auto-advance during interaction, and expose pause/mute clearly. Check source video captions; no caption implementation was identified in the player, but captions may be embedded in media.

## Shared design system

Keep the existing Lora display and Plus Jakarta Sans body pairing, dark green primary action, and warm neutral canvas. Consolidate the many screen-specific colors and radii into a smaller set of semantic roles. Use color to communicate state and hierarchy, with text/icons as well as color for status.

Suggested component contract: one primary action per task area; consistent secondary button; shared product card and variant picker; shared empty/loading/error block; shared status chip; standard form label/helper/error; shared sticky transactional footer. Adopt a predictable 4/8/12/16/24/32 spacing scale. Use restrained shadows and fewer nested cards so that spacing and type carry the hierarchy.

Accessibility acceptance: Flutter guideline checks for target size, labels, and contrast; TalkBack/VoiceOver task walkthroughs; 320/360/390/412 logical-pixel widths; 1×/1.3×/2× text scaling; long product names and addresses; keyboard open; safe-area insets; reduced motion. Flutter documents the relevant [accessibility testing APIs](https://docs.flutter.dev/ui/accessibility/accessibility-testing) and [design guidance](https://docs.flutter.dev/ui/accessibility/ui-design-and-styling). The proposed typography sizes are design defaults, not a claim of compliance. Actual rendered contrast remains unmeasured.

## Delivery order and validation

1. **Reliability and trust:** OTP normalization; stale delivery results; Rx eligibility; post-order payment recovery; search/history error states; production environment visibility; inaccurate labels and policy/support consistency.
2. **Core shopping UI:** readable product cards and touch targets; short relevant Home; clearer PDP; cart readiness before offers; checkout reasons and next actions. Retain the current brand while simplifying layout.
3. **Care and retention:** consistent care-channel names; resilient intake/uploads; honest reminder status; account organization; language and video accessibility improvements.
4. **Validate the proposed information architecture:** run representative tasks with pet owners and livestock customers before committing to a new bottom navigation. Ask users to find a suitable pack, determine delivery, recover from a failed payment, upload a prescription, resume a care conversation, and locate the next reminder. Record completion, errors, time, and comprehension rather than aesthetic preference alone.

Track search-to-product rate, add-to-cart rate, checkout completion by payment mode, delivery-check failures, payment recovery success, prescription upload completion, care-intake abandonment, and repeat-order completion. Establish a baseline before setting uplift targets. Audit analytics semantics first: checkout currently logs purchase immediately after order creation and before online payment, so it is not a reliable paid-conversion measure by itself. Record order creation and payment confirmation separately, deduplicate events, and avoid collecting symptoms, prescriptions, or other sensitive content in analytics.

The passing suite is a useful regression baseline. Add targeted tests for the confirmed state failures and accessibility criteria when implementing fixes. It does not substitute for a rendered-device pass, real gateway/backend integration checks, or usability research.
